# MemGPT: Towards LLMs as Operating Systems

- **原文**：https://arxiv.org/abs/2310.08560
- **PDF**：https://arxiv.org/pdf/2310.08560
- **HTML**：https://arxiv.org/html/2310.08560

## 研究问题

固定长度的 LLM context window 如何支持远超窗口大小的长期文档分析和多轮对话？

## 核心方法

MemGPT 借鉴操作系统虚拟内存：把当前可见的 context 视作主存，把 context 外部的数据视作磁盘/外部存储。Agent 可以通过函数调用在不同层级间搬运信息，并用控制流中断处理外部事件。

## 关键贡献

- 把 context window 看作稀缺的工作内存，而不是全部记忆。
- 通过外部存储与主动 paging，构造“虚拟上下文”的效果。
- 将记忆管理与 agent 控制流结合，支持在一个任务中反复修改上下文。

## 结果与适用边界

论文在长文档分析和多 session 对话两个场景展示了收益。它是分层记忆和上下文管理的重要架构先例，但不等于解决了记忆内容是否真实、何时遗忘、何时主动触发的问题。

## 对工程 Agent 的启发

可把 repo 事实、Jira 历史、PR 决策、用户偏好和当前任务状态放在不同存储层；运行时只把当前任务真正需要的内容召回。不要把整个项目历史无差别塞进 prompt。
