# ExecCritic: Learn to Test, Test to Improve for Coding Agents

- **原文**：https://arxiv.org/abs/2609.09133
- **PDF**：https://arxiv.org/pdf/2609.09133
- **HTML**：https://arxiv.org/html/2609.09133
- **代码**：https://github.com/MSR-Orchard/execcritic

## 研究问题

当 Agent 同时编写 patch、测试和停止条件时，可能出现共模错误：代码和测试都基于同一个错误理解，导致错误 patch 通过错误测试。

## 核心方法：Test → Verify → Revise

1. Test agent 独立探索 repo，生成 repository-native test、执行命令和行为契约。
2. Fail-closed harness 验证测试能执行，并要求它在 buggy base 上失败。
3. Harness 冻结测试，之后 Repair agent 只能修改源代码，不能修改测试。
4. 通过固定测试的执行反馈驱动 Repair agent 迭代；最终仍由官方隐藏评测决定正确性。

## 关键结果

在 SWE-bench Verified 上，测试质量决定反馈价值：固定 Repair agent 时，基础 Test agent 生成的测试将成功率从 no-test baseline 61.2% 降至 57.3%；GPT-5.6-sol 生成的测试则提升至 65.3%。角色专项训练后，组合系统达到 72.6%。

## 关键局限

72.6% 是包含训练、测试生成和多轮修复的整体系统结果，不是 compute-matched 的单变量测试增益。独立生成减少了同一轨迹的耦合，但两个 Agent 仍可能共享错误的需求理解。

## 对工程 Agent 的启发

这是最贴近 Jira → PR 的架构：
- Agent 产出测试建议；
- 独立验证服务检查测试是否能区分 buggy base 与 candidate patch；
- 测试被 freeze；
- Repair agent 无权改验收标准；
- 最终 PR 是否通过由外部 CI / hidden tests / reviewer 判定。
